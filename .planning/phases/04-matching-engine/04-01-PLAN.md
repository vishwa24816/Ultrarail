# Plan 04-01: Matcher core — exact settle, settled-set guard, exception queue

## Goal

Rail confirmations become settlements exactly once; anything non-confident lands visible in the exception queue.

## Threat model

- Double-settle: the settled-set check and the settle-event append happen in the same writer-task turn — no interleaving possible. Restart rebuilds the set from event replay before serving (mark ready only after).
- False confident match: missing rail fields (old producers) NEVER auto-settle — absent field = non-confident, routed to exceptions.
- Forged confirmations: confirmations accepted only over the authenticated bank WS plane (Phase 3 keys); unknown rail refs go to exceptions, never settle an unknown tx.
