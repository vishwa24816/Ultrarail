# Plan 05-01: Backup/restore + key rotation without downtime

## Goal

The two unowned gaps closed: journals are backup-restorable and keys rotate mid-load with zero 401s.

## Threat model

- Backup of a live tail: procedure mandates graceful shutdown first; restore replays (wal-db truncates torn tails). A live-copy fallback is documented but NOT the tested path.
- Rotation window abuse: dual acceptance is time-boxed (ROTATION_WINDOW_SECS, default 300); outside the window only the new key works. Old key use during window is audit-logged.
- Key file exposure: `*_KEYS_FILE` must be owner-read-only; boot warns (and test asserts the warning) when permissions are loose. On Windows: read-only attribute check.
