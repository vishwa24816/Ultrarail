# Plan 02-03: TTL idempotency + DLQ + bench proof

## Goal

Keys expire (TTL), expiries/conflicts land in an inspectable DLQ, and the bench proves the queueing collapse is gone.

## Threat model

- Post-TTL double-charge: same key after expiry = NEW payment by documented contract; API response includes `idempotency: "replayed" | "fresh"` so clients can distinguish. Never silently treat as new without the flag.
- DLQ poisoning the hot path: DLQ writes are fire-and-forget best-effort (own WAL, no sync-before-ack on DLQ); a DLQ failure must never fail the payment.
- Clock games: expiry uses server monotonic wall time persisted per record (`expires_ms` in journal record); replay recomputes from stored timestamps, not boot time.
