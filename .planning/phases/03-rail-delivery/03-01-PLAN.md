# Plan 03-01: Delivery worker + terminal failures + status query

## Goal

Accepted txs get delivered with retries, UNKNOWN discipline, bank terminal failures, and a queryable status. The core money-safety plan.

## Threat model

- Double-submit: reconcile-before-resubmit is MANDATORY; worker holds per-tx `inflight` flag so two batches never submit the same tx.
- Terminal bypass: classification happens BEFORE backoff scheduling; a `transient` label can never come from a bank `failed{reason}` message.
- Status oracle gap: `GET /payments/:id` on unknown id returns 404, never a guess; post-TTL ids return 410 (key expired contract from Phase 2).
- Fake bank events: `tx.failed` accepted only over authenticated bank WS (keys land in 03-04; until then localhost-only comment, same as existing WS).
